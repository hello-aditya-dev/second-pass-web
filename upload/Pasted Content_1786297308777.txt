0. CONFIRMED ROOT CAUSE
────────────────────────────────────────────────────────────

The current production defect has been diagnosed.

There are MULTIPLE interacting problems.

Do not rediscover them from scratch and do not ignore any of them.

ROOT CAUSE A — CONTENT COLLECTION ONLY LOADS `.md`

Current:

src/content.config.ts

contains approximately:

loader: glob({
  base: "./src/content/articles",
  pattern: "**/*.md"
})

Therefore `.mdx` articles are NOT currently part of the Astro content collection.

However, some newer/fixed article versions exist as `.mdx`.

This means edits have been made to `.mdx` files that production never uses.

The old broken `.md` files remained authoritative.

That is why fixes appeared correct in the repository but did not fix production.

ROOT CAUSE B — DUPLICATE ARTICLE SOURCES

There are cases such as:

cheapest-ai-model-not-cheapest-system.md

AND

cheapest-ai-model-not-cheapest-system.mdx

for the same conceptual article/slug.

This is unacceptable.

There must be EXACTLY ONE canonical content source for each article.

ROOT CAUSE C — BAD MATH SENTINELS IN OLD `.md`

The live `.md` source contains literal values such as:

24182
24183
24190
24191

These were apparently introduced by a broken publication-package conversion step
as replacement/sentinel values for display-math delimiters.

Example broken source:

24182
C_{\text{system}} =
C_{\text{direct}} +
...
24183

Those are ordinary text to Markdown.

KaTeX never receives the equation.

They must be removed from source.

Do NOT hide them with CSS.

ROOT CAUSE D — SINGLE `$` COLLIDES WITH CURRENCY

SECOND / PASS writes extensively about money.

Current remark-math behavior treats single-dollar pairs as inline math.

So ordinary prose like:

Suppose one model costs $1 and succeeds half the time.
Another costs $3 and succeeds every time.

can be parsed approximately as:

$1 and succeeds half the time. Another costs $

and sent to KaTeX.

That produces broken output such as:

1andsucceedshalfthetime.Anothercosts

This is why normal English appears compressed, italicized and mathematically styled.

The same problem affects phrases like:

$5/M input and $30/M output

$4.50 per review ... $0.0768

$2 per million ... $10 per million

ROOT CAUSE E — CORRUPTED EQUATIONS BECOME MARKDOWN HEADINGS

Once display equations lose their math delimiters, lines containing only:

=

can be interpreted as Markdown Setext-heading syntax.

This caused equations to become giant accidental H1s.
