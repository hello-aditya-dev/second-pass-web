3. TABLE RESPONSIVENESS — HIGH PRIORITY
────────────────────────────────────────────────────────────

Confirmed issue:

Current CSS contains approximately:

.article-body table {
  width: 100%;
  min-width: 620px;
}

and:

.table-wrap {
  overflow-x: auto;
}

But actual Markdown-generated article tables render as:

<table>...</table>

without a `.table-wrap`.

This means a 620px table can overflow a 375px/390px/430px viewport.

Fix this globally.

DO NOT require authors to manually wrap every table.

Implement a renderer-level solution.

Preferred approach:

Create a very small local rehype plugin/transform that wraps article tables:

<div class="table-wrap" role="region" tabindex="0" aria-label="Scrollable data table">
  <table>...</table>
</div>

Use appropriate accessibility semantics.

Do not add a heavy framework.

Do not add a JavaScript table library.

Do not convert Markdown tables to images.

All future Markdown tables should automatically inherit this behavior.

Required CSS approximately:

.table-wrap {
  width: 100%;
  max-width: 100%;
  overflow-x: auto;
  -webkit-overflow-scrolling: touch;
  margin: 2rem 0;
}

.table-wrap table {
  margin: 0;
}

On mobile, keep cells readable rather than crushing them.

A minimum table width is acceptable INSIDE the scroll container.

Page-level overflow is not acceptable.

Verify specifically on:

/articles/no-universal-long-context-premium

because it contains the provider comparison table.
